О проекте

ExampleAPI — учебное серверное приложение на ASP.NET Core с контроллерами, сервисами, SQLite и JWT-аутентификацией. Реализованы регистрация и вход, получение списка пользователей администратором, загрузка, просмотр и скачивание файлов.

6методов API
3контроллера
5таблиц БД
30 минсрок JWT

Модели товаров и заказов присутствуют в БД, но контроллеров для управления товарами и заказами в этой версии нет.

Запуск

Для запуска нужен .NET SDK 9. Проект содержит готовую SQLite-базу и автоматически создаёт её рабочую копию при первом старте.

  1. Клонируйте репозиторий и перейдите в каталог приложения.
  2. Восстановите пакеты и запустите HTTP-профиль.
  3. Откройте Swagger по адресу http://localhost:5239/swagger.
bash
git clone https://github.com/Getrengen/ExampleAPI.git
Адрес Назначение
http://localhost:5239/swagger Swagger UI
http://localhost:5239/ Документация из wwwroot/Description.html
https://localhost:7249 HTTPS при запуске с профилем https

Подготовка базы при старте

Program.cs вызывает SQLiteBdManager.Initialize(). Менеджер создаёт папку TestAPI в каталоге, который возвращает Environment.SpecialFolder.MyDocuments. Если рабочей БД ещё нет, он копирует исходный файл из Infrastructure рядом с собранным приложением.

На Windows целевой путь обычно выглядит так: C:\Users\<пользователь>\Documents\TestAPI\TestAPIBD_test_data.db. Фактический каталог документов может отличаться. MyDbContext получает строку подключения из SQLiteBdManager.ConnectionString;

Существующая рабочая БД не перезаписывается при старте. Обновление исходной БД в репозитории не обновляет ранее созданную копию. Если исходного файла нет и рабочая копия ещё не создана, запуск прерывается с FileNotFoundException.

Файл Infrastructure/TestAPIBD_test_data.db копируется в выходной каталог с настройкой PreserveNewest. Папка загружаемых файлов Files остаётся относительно рабочего каталога. Поэтому запускайте приложение из каталога проекта, как в примере выше.

Запуск в Linux

В текущем коммите GetSourcePath() собирает путь с обратными слешами. Для Linux перед запуском замените реализацию на платформонезависимую:

C# · рекомендуемая замена для Linux 
            private static string GetSourcePath()
{
    return Path.Combine(
        AppContext.BaseDirectory,
        "Infrastructure",
        FileName);
}

Целевая папка определяется через MyDocuments; если среда возвращает пустую строку, TestAPI окажется относительно рабочего каталога.

Чтобы разместить эту документацию в приложении, скопируйте HTML-файл в wwwroot/Description.html: обработчик маршрута / уже настроен.

Справочник API с методами

POST

Вход

/api/AuthReg/Login

Публичный

Входные данные

Query: Login, Password

Ответы

200 — объект с access_token и token_type; 401 — вход отклонён.

curl
curl -X POST 'http://localhost:5239/api/AuthReg/Login?Login=demo&Password=ExamplePass123'
Пример ответа
{
  "access_token": "<JWT>",
  "token_type": "Bearer"
}

Параметры не читаются из JSON. Пустые поля, отсутствующий пользователь или неверный пароль приводят к null в сервисе и затем 401. ASP.NET Core также может вернуть 400 на этапе привязки/валидации. Пользователь должен иметь связанную роль с непустым Name: CreateToken обращается к user.Role.Name без проверки.

POST

Регистрация

/api/AuthReg/Register

Публичный

Входные данные

Form: Login, FullName, PassHash

Ответы

200 — пустой ответ; 400 — отказ сервиса либо ошибка валидации.

curl
curl -X POST 'http://localhost:5239/api/AuthReg/Register' \
  --data-urlencode 'Login=demo' \
  --data-urlencode 'FullName=Иван Иванов' \
  --data-urlencode 'PassHash=ExamplePass123'

Несмотря на имя PassHash, клиент передаёт обычный пароль. Сервис сам хеширует его через PasswordHasher и записывает RoleID=2 (Пользователь). Уникальность Login сервисом не проверяется. Исключения SaveChanges не перехватываются и не преобразуются в 400.

GET

Список пользователей

/api/Admin/GetAllUsers

JWT · Администратор

Входные данные

Без параметров

Ответы

200 — массив DTO; 401/403 — отказ в доступе.

curl
curl 'http://localhost:5239/api/Admin/GetAllUsers' \  -H 'Authorization: Bearer <access_token>'
Пример ответа
[
  {
    "fullName": "Иван Иванов",
    "login": "demo",
    "role": "Пользователь"
  }
]

Пример ответа условный. Поля ID и PassHash не возвращаются. Пагинации и фильтрации нет. Если пользователей нет, возвращается []. FullName и название роли в модели могут быть null, хотя DTO объявлен со string.

POST

Загрузка файла

/api/Files/upload

Публичный

Входные данные

Multipart/form-data: file

Ответы

200 — текст «имя has been uploaded»; 400 — файл отсутствует/пустой, имя уже занято либо SaveFile вернул false.

curl
curl -X POST 'http://localhost:5239/api/Files/upload' \
  -F 'file=@./Test.txt'
Пример ответа
Test.txt has been uploaded

Сохраняется в Files относительно рабочего каталога. Path.GetFileName оставляет только имя файла. Если файл уже существует, SaveFile возвращает false и контроллер отвечает 400 с текстом «Не удалось сохранить файл». Для создания используется FileMode.CreateNew: перезапись существующего файла не допускается. При одновременной загрузке одного имени возможен IOException; он не перехватывается. Ограничения расширений и размеров на уровне приложения не заданы; ограничения хоста возможны. Ошибки файлового ввода-вывода не перехватываются.

GET

Предпросмотр

/api/Files/see

Публичный

Входные данные

Query: fileName

Ответы

200 — поток файла; 400 — пустое имя/ошибка привязки; 404 — файл не найден.

curl
curl 'http://localhost:5239/api/Files/see?fileName=Test.txt'

Возвращает File(stream, contentType), без имени скачиваемого файла. GetFile отклоняет точное имя TestAPIBD_test_data.db и возвращает null, что даёт 404. Рабочая БД хранится отдельно от Files. Возможность предпросмотра зависит от браузера и MIME-типа. Расширения проверяются регистрозависимо: .PNG попадёт в тип по умолчанию.

GET

Скачивание

/api/Files/download

Публичный

Входные данные

Query: fileName

Ответы

200 — файл с Content-Disposition для скачивания; 400 — пустое имя/ошибка привязки; 404 — файл не найден.

curl
curl 'http://localhost:5239/api/Files/download?fileName=Test.txt' \
  --output downloaded.txt

Используется application/octet-stream и переданное fileName в File(stream, type, fileName). При открытии файла сервис оставляет только базовое имя через Path.GetFileName. GetFile отклоняет точное имя TestAPIBD_test_data.db; контроллер отвечает 404.

База данных

Исходная база находится в Infrastructure/TestAPIBD_test_data.db. Приложение работает с копией в MyDocuments/TestAPI/TestAPIBD_test_data.db, подготовленной SQLiteBdManager. Эта копия расположена отдельно от хранилища загружаемых файлов.

Схема проверена по включённому SQLite-файлу, а связи — также по MyDbContext. Количество записей относится к снимку репозитория.

Первичные ключи — INTEGER AUTOINCREMENT. Все внешние ключи допускают NULL. В AppUser.Login нет ограничения UNIQUE. Price представлен целым числом, единица измерения в коде не определена. CreatedDate хранится как TEXT в SQLite и отображается на DateTime? в модели.

В тестовой БД пароли имеют разные форматы: пять значений длиной 64 символа и одно длиной 84. Это не подтверждает совместимость всех записей с PasswordHasher. Для воспроизводимого теста зарегистрируйте нового пользователя через API; пароли из тестовой БД здесь не публикуются.

Проверка через Swagger

Действия ниже описывают проверку приложения в Swagger UI. Учётные данные и примеры ответов в справочнике иллюстративные.

  1. Запустите приложение и откройте http://localhost:5239/swagger.
  2. В POST /api/AuthReg/Register нажмите Try it out. Заполните Login, FullName и PassHash. В PassHash передайте обычный пароль — сервис сам вычислит хеш. Нажмите Execute; ожидается 200.
  3. В POST /api/AuthReg/Login укажите тот же Login и пароль в Password. Ожидается 200 с access_token и token_type.
  4. Скопируйте access_token, нажмите Authorize и вставьте только токен, без слова Bearer. Нажмите Authorize, затем Close.
  5. Вызовите GET /api/Admin/GetAllUsers. Новый пользователь получает RoleID=2 (Пользователь), поэтому ожидается 403.
  6. Для проверки административного доступа назначьте своему тестовому пользователю RoleID=1 в рабочей копии БД. Затем заново выполните Login и замените токен в Authorize: роль в уже выданном токене не меняется.
  7. Повторите GetAllUsers с административным токеном. Ожидается 200 и массив с fullName, login, role.
  8. Загрузите файл с новым именем через POST /api/Files/upload. Ожидается 200. Повторная загрузка того же имени должна вернуть 400.
  9. Передайте имя загруженного файла в GET /api/Files/see и GET /api/Files/download. Ожидается 200; для отсутствующего файла — 404.

Передача и действие токена

HTTP
Authorization: Bearer <access_token>

JWT действует 30 минут. Он содержит sub (ID пользователя), name (логин) и role (название роли). Административный контроллер требует точное название Администратор. Ключ подписи генерируется при старте, поэтому после перезапуска API необходимо снова войти.

Результат AdminЗначение
401 UnauthorizedТокен отсутствует, недействителен или истёк
403 ForbiddenТокен принят, но нет роли Администратор
200 OKДоступ разрешён; результат — массив пользователей

Swagger применяет схему Bearer глобально, поэтому замочки могут отображаться и у публичных операций. Login, Register и Files не требуют токена. Фактическую защиту задают атрибуты контроллеров.

Изменяйте рабочую БД, а не исходный файл в Infrastructure. Рабочая копия сохраняется между запусками. Если вход с пользователем из тестовой БД не проходит, сначала проверьте вход с новым пользователем, зарегистрированным через API.
