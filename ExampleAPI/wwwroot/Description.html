ExampleAPI

Учебный сервер для работы с пользователями, товарами, заказами и файлами. От первого запроса в Swagger до разграничения доступа с JWT.

О проекте

ExampleAPI показывает, как устроено серверное приложение на C#: контроллер принимает HTTP-запрос, сервис выполняет операцию, EF Core обращается к SQLite, а клиент получает результат.

5контроллеров
15HTTP-методов
5основных таблиц
30 минсрок действия JWT

Технологии

.NET 9 / ASP.NET Core Web API, Entity Framework Core, SQLite, JWT Bearer, стандартный PasswordHasher<T> и Swagger UI.

Проект предназначен для занятий и экспериментов. Он не является готовой системой для хранения реальных персональных данных или развёртывания в интернете.

Установка и запуск

Понадобятся Git и .NET SDK 9. Команды выполняйте из терминала; для Windows, Linux и macOS синтаксис одинаковый.

Терминал
git clone https://github.com/Getrengen/ExampleAPI.git
cd ExampleAPI/ExampleAPI
dotnet restore
dotnet run --launch-profile http
АдресЧто откроется
http://localhost:5239/swaggerSwagger UI для проверки API
http://localhost:5239/Эта страница, когда она лежит в wwwroot/Description.html
Если в консоли выведен другой адрес, используйте его. Чтобы разместить эту страницу в проекте, сохраните файл как ExampleAPI/wwwroot/Description.html внутри репозитория.

Где находится база данных?

Исходная тестовая SQLite-база располагается в Infrastructure/TestAPIBD_test_data.db. При первом запуске SQLiteBdManager готовит рабочую копию в папке TestAPI внутри каталога «Документы» пользователя.

Типичный путь в Windows
C:\Users\<пользователь>\Documents\TestAPI\TestAPIBD_test_data.db
Повторный запуск не перезаписывает существующую рабочую базу. Если изменения не видны в редакторе SQLite, убедитесь, что открыта рабочая копия, а не исходный файл. Для Linux проверьте, что в SQLiteBdManager.GetSourcePath() путь составлен через Path.Combine().

Структура приложения

Проект разделён на части так, чтобы каждую ответственность можно было объяснить отдельно.

ПапкаЗадача
ControllersМаршрутизация, авторизация и возврат HTTP-ответов.
ServiceБизнес-логика и взаимодействие с данными.
DTOsМодели для входных и выходных данных.
EntitiesСущности и типизированный результат Result<T>.
InfrastructureMyDbContext и подготовка SQLite.
FilesДемонстрационная директория для файлов.
wwwrootСтатические файлы, включая эту документацию.

От запроса до ответа

Клиент → Controller → Service → DbContext → SQLite → Result<T> → HTTP-ответ.

ResultStatus.Success преобразуется в 200 OK, NotFound — в 404, InvalidData — в 400, Conflict — в 409.

JWT и роли

После успешного входа сервер выдаёт JWT с ID пользователя (sub), логином (login) и названием роли (role). Токен нужно передавать в запросах к защищённым методам.

HTTP-заголовок
Authorization: Bearer <JWT_токен>
ДоступКакие операции доступны
Без входаРегистрация, вход, получение каталога и методы Files.
Любой авторизованныйСобственный профиль и заказы в UserController.
МенеджерДобавление и редактирование товаров.
АдминистраторСписок пользователей и изменение данных учётных записей.
401 Unauthorized обычно означает отсутствующий, неверный или просроченный токен; 403 Forbidden — действительный токен без подходящей роли. Новая роль не появляется в старом JWT: войдите снова.
Доступны без токена

Авторизация и регистрация

Здесь пользователь создаёт учётную запись и получает JWT для обращения к защищённым методам.

POST

Регистрация пользователя

/api/AuthReg/Register
Доступ: Публичный

Создаёт нового пользователя с ролью «Пользователь» (RoleID = 2). Клиент передаёт пароль обычной строкой, сервер хеширует его перед сохранением.

Параметры
JSON-тело: login, fullName, passHash
Ответ
200 — ID созданного пользователя; 400 — некорректные данные; 409 — логин занят.
Пример тела запроса · JSON
{
  "login": "student01",
  "fullName": "Иван Иванов",
  "passHash": "ExamplePass123"
}

Примечание. Имя поля passHash историческое. Передавать уже захешированный пароль не требуется. Используйте только вымышленные учебные пароли.

POST

Получение JWT

/api/AuthReg/Login
Доступ: Публичный

Проверяет логин и пароль и при успехе возвращает токен с данными пользователя и его ролью.

Параметры
JSON-тело: login, password
Ответ
200 — данные JWT; 400 — логин или пароль не прошли проверку.
Пример тела запроса · JSON
{
  "login": "student01",
  "password": "ExamplePass123"
}

Примечание. После получения токена нажмите Authorize в Swagger. JWT действителен 30 минут; после перезапуска сервера ключ подписи меняется.

Публичный каталог и методы авторизованного пользователя

Товары и заказы

Каталог открыт всем. Для просмотра собственного профиля и создания заказов необходимо войти.

GET

Список товаров

/api/User/GetAllProducts
Доступ: Публичный

Возвращает наименование, цену и описание товаров. Если товаров нет, возвращается пустой массив.

Параметры
Без параметров
Ответ
200 — массив товаров (в том числе []).

Примечание. Используется DTO AddGiveProduct. Пример результата зависит от данных в рабочей базе.

GET

Собственный профиль

/api/User/GetMe
Доступ: Любой авторизованный

Находит пользователя по ID из JWT и возвращает ФИО, логин и название роли.

Параметры
Заголовок Authorization: Bearer <JWT>
Ответ
200 — данные пользователя; 401 — токен отсутствует или ID не определён; 404 — пользователь не найден.

Примечание. ID берётся из claim sub токена. Отправлять userId в параметрах запроса не нужно.

GET

Мои заказы

/api/User/GetOrder
Доступ: Любой авторизованный

Возвращает заказы текущего пользователя с датами, товарами, количеством и ценой.

Параметры
Заголовок Authorization: Bearer <JWT>
Ответ
200 — массив заказов (при отсутствии заказов — []).

Примечание. Метод называется GetOrder, но возвращает список всех заказов пользователя.

POST

Создать заказ

/api/User/CreateOrder
Доступ: Любой авторизованный

Создаёт заказ из списка позиций. ID пользователя считывается из JWT, а не из тела запроса.

Параметры
JSON-тело: массив объектов productId и quantity
Ответ
200 — ID нового заказа; 400 — пустой заказ / некорректное количество; 404 — пользователь или товар не найден.
Пример тела запроса · JSON
[
  {
    "productId": 1,
    "quantity": 2
  },
  {
    "productId": 2,
    "quantity": 1
  }
]

Примечание. Товары с такими ID должны существовать в рабочей БД. Для учебной версии лучше не повторять один productId несколько раз в заказе.

Требуется роль «Менеджер»

Операции менеджера

Менеджер создаёт товары, полностью заменяет их данные или изменяет отдельные поля.

POST

Добавить товар

/api/Manager/AddProduct
Доступ: Менеджер

Создаёт новый товар. Название, описание и цена обязательны; цена должна быть больше нуля.

Параметры
JSON-тело: name, price, description
Ответ
200 — ID товара; 400 — некорректные данные; 401/403 — нет доступа.
Пример тела запроса · JSON
{
  "name": "Клавиатура",
  "price": 1900,
  "description": "Проводная клавиатура"
}

Примечание. Текущая реализация возвращает 200. Для создания ресурса в дальнейшем можно использовать 201 Created.

PUT

Полностью обновить товар

/api/Manager/Product/{id}
Доступ: Менеджер

Заменяет переданные поля существующего товара. Для PUT ожидается полный набор данных.

Параметры
Маршрут: id; JSON-тело: name, price, description
Ответ
200 — обновлённый товар; 400 — некорректные данные; 404 — товар не найден.
Пример тела запроса · JSON
{
  "name": "Клавиатура Pro",
  "price": 2400,
  "description": "Механическая клавиатура"
}

Примечание. Например: PUT /api/Manager/Product/1. Поля name и description должны быть заполнены.

PATCH

Изменить отдельные поля товара

/api/Manager/Product/{id}
Доступ: Менеджер

Позволяет передать только изменяемые свойства, остальные значения сохраняются.

Параметры
Маршрут: id; JSON-тело: необязательные name, price, description
Ответ
200 — обновлённый товар; 400 — некорректное значение; 404 — товар не найден.
Пример тела запроса · JSON
{
  "price": 2100
}

Примечание. При обычном DTO пропущенное поле и поле с null не различаются. В этой реализации null означает «не менять», а не «очистить поле».

Требуется роль «Администратор»

Операции администратора

Администратор просматривает пользователей, изменяет роли и основные данные учётных записей.

GET

Список пользователей

/api/Admin/GetAllUsers
Доступ: Администратор

Возвращает ФИО, логин и роль каждого пользователя без хешей паролей.

Параметры
Только Authorization: Bearer <JWT>
Ответ
200 — массив пользователей; 401 — нет токена; 403 — недостаточно прав.

Примечание. Если пользователей нет, возвращается [].

PATCH

Изменить роль пользователя

/api/Admin/UpdateUserRole
Доступ: Администратор

Меняет роль выбранной учётной записи по числовому идентификатору роли.

Параметры
Query: userID, newRoleID
Ответ
200 — обновлённые сведения; 404 — пользователь или роль не найдены.

Примечание. Пример: /api/Admin/UpdateUserRole?userID=5&newRoleID=3. Уже выданный пользователю JWT не обновится автоматически.

PUT

Обновить учётную запись

/api/Admin/UpdateUser
Доступ: Администратор

Обновляет ФИО, логин и роль существующего пользователя.

Параметры
Query: userID; JSON-тело: fullName, login, roleID
Ответ
200 — обновлённые сведения; 400 — некорректные данные; 404 — пользователь/роль не найдены; 409 — логин занят.
Пример тела запроса · JSON
{
  "fullName": "Иван Иванов",
  "login": "ivan_new",
  "roleID": 2
}

Примечание. Пример: PUT /api/Admin/UpdateUser?userID=5. Тело отправляется в формате application/json.

В текущей версии доступны без авторизации

Загрузка и получение файлов

Отдельный пример работы с IFormFile, файловыми потоками и заголовками ответа.

POST

Загрузить файл

/api/Files/upload
Доступ: Публичный

Получает один файл и сохраняет его в папке Files приложения.

Параметры
multipart/form-data: поле file
Ответ
200 — файл загружен; 400 — пустой файл либо сохранение отклонено.

Примечание. Повторное имя файла может привести к отказу в сохранении. В учебной версии нет полноценной проверки допустимых типов и размеров файлов.

GET

Предпросмотр файла

/api/Files/see
Доступ: Публичный

Возвращает содержимое файла с MIME-типом, который выбирается по расширению. Браузер может показать изображение, PDF или текст прямо на странице.

Параметры
Query: fileName
Ответ
200 — содержимое файла; 400 — не передано имя; 404 — файл не найден.

Примечание. Пример: /api/Files/see?fileName=Test.txt. Предпросмотр HTML потенциально небезопасен на публичном сервере.

GET

Скачать файл

/api/Files/download
Доступ: Публичный

Отдаёт содержимое файла как вложение с Content-Disposition для скачивания.

Параметры
Query: fileName
Ответ
200 — скачивание файла; 400 — не передано имя; 404 — файл не найден.

Примечание. Пример: /api/Files/download?fileName=Test.txt.

База данных

В проекте используется SQLite с пятью основными таблицами. Взаимодействие с ними выполняется через MyDbContext и LINQ.

ТаблицаОсновные данныеСвязи
RoleID, название ролиОдна роль у многих пользователей
AppUserID, логин, ФИО, хеш пароля, рольСвязана с Role и Order
ProductID, название, цена, описаниеСвязана с OrderProduct
OrderID, пользователь, дата созданияСвязана с AppUser и OrderProduct
OrderProductID, заказ, товар, количествоСвязывает Order и Product

Как связаны таблицы

Role (1) → (N) AppUser (1) → (N) Order (1) → (N) OrderProduct (N) ← (1) Product

В справочнике ролей учебной базы используются названия: Администратор, Пользователь, Менеджер. В коде регистрации для нового пользователя указывается RoleID = 2.

Nullable-свойства C# и ограничение NOT NULL в SQLite — не одно и то же. При изменении модели проверьте фактическую схему рабочей базы. Число тестовых записей может отличаться после запуска.

Проверка через Swagger: пошагово

  1. Запустите проект и откройте http://localhost:5239/swagger.
  2. В POST /api/AuthReg/Register отправьте JSON с login, fullName, passHash. Для теста используйте вымышленные данные.
  3. В POST /api/AuthReg/Login передайте те же логин и пароль в JSON. Скопируйте полученный JWT.
  4. Нажмите Authorize и вставьте JWT (без префикса Bearer, если Swagger использует HTTP Bearer-схему). Подтвердите авторизацию.
  5. Выполните GET /api/User/GetMe, затем GET /api/User/GetAllProducts.
  6. Отправьте список существующих товаров в POST /api/User/CreateOrder и проверьте его через GET /api/User/GetOrder.
  7. Попробуйте метод Admin с обычным пользовательским токеном: ожидается 403.
  8. Отдельно проверьте загрузку файла и методы see и download.
Для запросов с ролью «Администратор» или «Менеджер» используйте специально подготовленные учебные аккаунты с соответствующими ролями. После изменения роли повторите вход.

О чём важно помнить

Ключ JWT

В текущем учебном коде ключ подписи генерируется при запуске. После перезапуска уже выданные токены становятся недействительными.

Работа с файлами

Методы файлов доступны анонимно. Для реального сервера нужны ограничения размера и расширений, управление доступом и безопасная выдача контента.

HTTP-статусы

Создание заказа или товара пока возвращает 200 OK. Статус 201 Created можно добавить при расширении ResultStatus.

Учебные данные

Не используйте реальные пароли и персональные сведения. Проверяйте изменения в рабочей копии SQLite.
